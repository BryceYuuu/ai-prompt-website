# 目录浏览层

浏览层只负责发现内容，不改模板原文、作者、许可或核验状态。

## 两层分类

- 顶层继续使用 `TAXONOMY.categories`：图片转换与六类文字任务
- 图片子类定义在 `assets/js/data.js` 的 `TAXONOMY.imageGroups`，每个条目 ID 只放入一组
- 当前方向为手办玩具、材质工艺、插画绘画、平面拼贴、微缩场景、摄影光影
- 未归组的新图片自动进入「其他风格」，仍可从全部列表、搜索和来源找到；没有内容的分组默认不展示
- 新内容先完成来源/许可审核，再由生成器进入目录，最后补图片子类。不要为展示排序修改原始提示词或重新许可第三方内容

## 来源

`HF_BROWSE.source` 从每条内容的来源证据派生筛选项：

- Threads 按原帖账号聚合，例如 `threads:inkacalinka`
- GitHub 按仓库聚合，例如 `github:jamez-bondos/awesome-gpt4o-images`
- 其他内容按来源名称聚合，保留可读的回退标签

账号/仓库是内容集合，不能据此替换原作者署名；原有封面署名、来源链接与详情许可保持不变。来源选项和数字从实际目录计算，不另存手写计数。

## URL 与状态

图片例：`#/library?cat=image&group=drawing&source=threads%3Ainkacalinka&sort=new`

文字例：`#/library?track=text&cat=code&q=review`

`group`、`source`、`cat`、`use`、`mood`、`q`、`track`、`sort` 与 `page` 都在 URL 中。改变条件回第一页；翻页与详情返回保留条件；刷新列表可恢复。详情返回位置仍采用原有同页内存方式，直接打开/刷新详情时回退到该条目的分类。

切换大类清除图片子类、来源、用途与气质，避免留下互相冲突的条件；关键词和排序继续保留。类型切换清除不兼容分类。清空图片筛选仍留在图片库，清空收藏筛选仍留在收藏。

搜索使用空格分隔的关键词 AND 匹配，对标题、别名、分组、作者、来源和提示词做不区分大小写的查找。仅收藏 ID 持久化；用户填写的材料继续只放内存，不进入 URL 或存储。

## 验证

- `npm test`：内容契约、来源许可与 UI 回归
- `npm run test:mutations`：验证回归测试能发现关键实现被破坏
- `CHROME_BIN=/path/to/chrome npm run test:browser`：真实浏览器点击、窄屏与溢出检查，需要允许浏览器启动的环境

新增 UI 回归包含分组完整性、未来内容回退、来源组合/计数、页码与返回、收藏范围、多词检索、非法/截断 URL、旧搜索不覆盖新导航、文字/图片卡片语义层级和输入转义。JSDOM 不提供真实布局，不能代替浏览器视觉检查。
